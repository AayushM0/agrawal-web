## What to build

Implement the backend Server Action layer, anti-fraud heuristics, rate limiting, and authorization barriers for member messaging in `src/actions/chat.ts`.

- Create `src/actions/chat.ts` exporting:
  - `sendMessage({ recipientMemberId, messageBody, conversationId? })`:
    - Requires authenticated session (`getSession()`).
    - Enforces rate limits: max 10 new conversation requests/day, max 60 messages/hour per member.
    - Runs in-stream anti-fraud regex scanner detecting UPI IDs (`[\w.-]+@[\w.-]+`), IFSC/bank accounts, external payment URLs, and scam keywords.
    - If conversation is `pending` and sender is the initiator, rejects follow-up spam until recipient accepts.
  - `getConversations()`:
    - Resolves caller's member ID from session.
    - Returns structured `{ active: Conversation[], requests: Conversation[] }` with unread count.
  - `getMessages(conversationId)`:
    - Enforces IDOR security: verifies caller is a participant; returns 403 / error otherwise.
    - Automatically marks incoming unread messages as read.
  - `respondToRequest({ conversationId, action: 'accept' | 'decline' | 'block' })`:
    - Updates conversation status; prevents blocked members from messaging.
  - `reportConversation({ conversationId, reason, details })`:
    - Captures an immutable thread snapshot and writes to `message_reports` for moderator audit.

## Acceptance criteria

- [ ] Unauthenticated callers are rejected with an authorization error
- [ ] Non-participants cannot fetch or read messages from private conversations (strict IDOR check)
- [ ] Messages containing UPI handles, bank numbers, or phishing triggers are flagged with anti-fraud metadata
- [ ] Rate limits prevent initiating more than 10 new conversation requests in a 24-hour window
- [ ] Two-stage message requests prevent initiators from sending further messages until accepted
- [ ] Automated Server Action tests pass 100%
