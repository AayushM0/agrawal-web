## What to build

Implement the core cryptographic engine and database schema foundations for password authentication.

- In `package.json`:
  - Install `bcryptjs` and `@types/bcryptjs` for pure-JavaScript bcrypt hashing across all environments.
- In `src/lib/db.ts` & `src/db/schema.sql`:
  - Add `password_hash TEXT` column to `households` table via automated `ensureSchema()`.
  - Add `password_hash TEXT` column to `members` table for self-claimed member accounts.
  - Create `login_attempts` table (`id`, `identifier`, `ip_address`, `success`, `created_at`) with index on `(identifier, ip_address, created_at DESC)`.
- In `src/lib/auth-crypto.ts` (new helper):
  - Password complexity validation schema using Zod (min 8 chars, 1 uppercase, 1 lowercase, 1 number, max 72 chars).
  - `hashPassword(password: string): Promise<string>` with bcrypt cost factor 12.
  - `verifyPassword(password: string, hash: string): Promise<boolean>` with timing-safe comparison.
  - `checkLoginLockout(identifier: string, ip: string): Promise<{ locked: boolean; remainingSeconds?: number }>` (5 failed attempts within 15 min triggers lockout).
  - `recordLoginAttempt(identifier: string, ip: string, success: boolean): Promise<void>`.

## Acceptance criteria

- [ ] `bcryptjs` is installed and compiles cleanly without native binding errors
- [ ] Database schema migrations run automatically via `ensureSchema()` on startup without error
- [ ] Password hashing produces valid `$2a$12$` formatted hashes
- [ ] Password complexity rejects passwords that are too short (<8) or lack required character variety
- [ ] 5 consecutive failed attempts lock the identifier/IP for 15 minutes, while success clears failure streak
- [ ] Unit tests in `tests/auth-crypto.test.mjs` verify hashing, validation, and lockout calculations
