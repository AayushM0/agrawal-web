# Issue 035: Gap-Free Serial Number Recycling Engine on Admin Rejection

## Objective
Prevent permanent burning of community serial numbers when applications are rejected by administrators. When an application is rejected, its serial number is released and recycled to the very next applicant, keeping the sequential registry intact and unbroken.

## Scope
- Modify `updateHouseholdStatus` in `src/lib/db.ts` and `moderate.ts`:
  - When `status === 'rejected'`, set `serial_no = NULL` on the household and all associated members.
- Upgrade `generateNextHouseholdNo` and `generateNextMemberSerialNo` in `src/lib/db.ts`:
  - Replace naive `MAX(num) + 1` with an atomic gap-detection query using `generate_series` and `NOT EXISTS`.
  - Reclaim the lowest available integer gap in the sequence.
- Ensure all allocations execute inside `pg_advisory_xact_lock(REGISTRATION_CONCURRENCY_LOCK_ID)` to guarantee concurrency safety.
